# 卒業研究：ここからの方針（2026年9月29日作成、11月9日改訂）

## 研究の中心

室内に置かれた小物が遠くて小さく映り、検出・追跡が不安定になる場面で、検出枠の周囲をどこまで切り出し、どう拡大して見直すか（超解像・通常拡大・切り出しのみ）を自動で選ぶ。通常のYOLO、固定の局所超解像、同倍率の通常拡大、動的倍率規則、学習による選択を**同じ元映像**で比較する。見るのは、正解枠に対する検出率、見失い・再検出、追跡IDの継続、追加処理時間である。比較的低スペックの機器への組み込みを目標とするため、精度は処理時間とのバランスで評価する。

検証は2段階で進める（11月の指導教員との相談で決定）。

1. **仮説の確認（カップ、COCO学習済みの `yolo26n.pt`）**：検出しやすい物で、撮影→注釈→比較→選択モデルの学習→評価を最後まで通し、仮説が正しいかを確かめる。
2. **本命の検証（鍵、自作の鍵検出器）**：仮説が支持されたら、研究テーマ（無人の室内で持ち去られると困る小物）に合わせて鍵で検証する。10月に作った鍵の検出器・学習データ・映像・比較結果はそのまま残してあり、`--model` と `--label key` で切り替えられる。

比較に使う動的倍率規則は、オフライン比較用の `rule`（[runner.py](../small_object_lab/research/runner.py)）である。ライブ画面の局所超解像とは、発火条件（信頼度の低下を差で判定する、見失い後0.75秒まで続ける）と局所推論の検出閾値（全方式共通の0.20）が異なるため、「ライブ画面と同一の規則」とは書かない。オフライン比較用の定義として固定する方針で、11/17に確認する。

対象は1個とし、撮影は本人が行う（被験者は使わない）。複数対象への拡張や不審行動の判定は、この比較の結果を確認してから検討する。

## 現在地（11/9）

10月の改善と結果は [10月のレポート](REPORT_202610.md) にまとめた。要点は次のとおり。

- 録画（ボタンでの開始・終了、欠落対策）、4方式の比較、切り出し候補の拡張（余白10〜300%、切り出しのみx1）、注釈ツール、選択モデルの学習処理は実装済み。
- 切り出して見直す処理では、**切り出す範囲（周りの写り込み）が成否を大きく左右する**（鍵の映像で、余白20%では3〜4割、余白100%では約8割を見つけ直せた）。カップでも、余白20%では周りが写らず判断できなかった。
- **超解像（FSRCNN）の効果は、使う検出器によって上がったり下がったりした**。原因は超解像の不具合ではなく、検出器がわずかな画像の変化に不安定なことにある。超解像の効果は、検出器の偶然性を除いて確かめる必要がある。
- 正解枠を付けた正式な検出率は、まだない。

実験操作と評価指標の詳細は [実験手順](RESEARCH_WORKFLOW.md) と [注釈・評価の定義](ANNOTATION.md) を参照する。

## 11/17に説明する内容

1. 正解枠を人が確認したカップの映像で、通常YOLO・固定局所超解像・通常拡大・動的倍率規則（必要に応じて学習による選択）を比較した結果。未確認フレームは検出率に算入しない。
2. カップが小さくなるにつれ、どの条件で検出・追跡が途切れ、局所処理の時間がどれだけ増えたか。切り出す範囲と拡大方法の効果を分けて示す。成功例だけでなく失敗例も示す。
3. 本番撮影（11/25〜11/28、カップ）の計画と、その後の鍵での検証の計画。10月に鍵で得た知見（切り出す範囲の重要性、超解像の効果が検出器によって変わること）も補足として示す。

## 実験の判断基準

- 各記録の `manifest.json` で完了・欠落・エラーを確認する。15秒ごとの枠付き保存画像は正解用の元映像に使わない。
- PCの結果画面またはandroid-camera-streamerアプリで記録開始から記録終了を押すまでが1つの撮影セッション（`session_id` ＝ 記録ID）になる。学習・調整・最終評価に分けたい撮影は、撮影ごとに記録を開始・終了し直して別のセッションにする。1回の撮影の間はカメラの位置と解像度を変えない。
- 撮影ごとに対象、解像度、カメラ位置、照明、対象の置き方を記録する。画面の「実物条件を記録」は `measurements.csv` に入り、元映像の `manifest.json` には残らないため、条件メモは記録IDと対応づけて別に残す。
- 最初は要因を混ぜず、遠近・横方向の位置・一部遮蔽・背景変更を別々の撮影にする。
- 比較は同じ元フレーム、同じ正解枠、同じ検出閾値で行う。超解像・同倍率の通常拡大・切り出しのみを同じ切り出し範囲で比較し、超解像そのものの寄与を確かめる。
- 超解像の効果を主張・否定するときは、1つの検出器の結果だけで判断しない（検出器を複数回学習したときのばらつき、またはCOCOの汎用モデルでの再現を確かめる）。
- 処理時間は、追加処理の発動率を含めた1フレームあたりの平均で評価する。組み込み先の想定が決まったら、その条件（CPUのみ・スレッド数の制限など）でも計測する。
- 学習・調整・最終評価は撮影セッション単位で分ける。同じ内容の映像を別IDとして混ぜない。最終評価用の映像はモデルの調整に使わない。
- 学習の報酬は「正解枠との一致から追加処理時間の罰を引いたもの」で、対象が完全に見えないフレームでの誤検出は罰しない。評価ではこれを誤検出として数える。また、学習は全フレームで行うが、学習方式が選択を行うのは不安定と判定したフレームだけである。この2点は結果の考察で明記する。
- 実データでの学習と最終評価が終わるまでは、ソフトウェアの動作確認を研究上の効果として報告しない。
